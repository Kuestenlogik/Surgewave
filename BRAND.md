# Surgewave brand guide

Quick reference for using the Surgewave name and mark in product UIs,
documentation, and partner integrations. Every logo file in
[`images/`](images/) is generated by
the shared branding tool,
[`scripts/branding/tool/generate-logos.mjs`](scripts/branding/tool/README.md)
(a pinned copy of `tools/branding` in the Kuestenlogik repository), from one
drawing, `scripts/branding/surgewave_mark_source.svg`, configured in
`scripts/branding/brand.json` (both pinned copies of `brand/products/surgewave`
in the Kuestenlogik repository, edited only there); the generator also copies the tab and
home-screen icons to the website, the docs theme and the Control UI. See
[`images/README.md`](images/README.md) for which file to use where.

---

## Wordmark

Use the literal word **Surgewave** as a wordmark — capitalised as shown,
one word, no hyphen, no inner caps (not "SurgeWave" or "surge wave").

| Context | Wording |
|---|---|
| Product name in prose | Surgewave |
| Package id / namespace | `Kuestenlogik.Surgewave.*` |
| Container repository / image name | `surgewave-broker`, `surgewave-control` |
| Tool / CLI command | `surgewave` |

## Primary mark (adaptive)

The canonical Surgewave mark — a stylised wave intersecting an upward
arc — is **theme-aware**: the blues stay across light and dark
backgrounds, while the ink colour switches between navy (on light) and
white (on dark). Use this variant **wherever the host surface controls
its own colour scheme** (web site, docs, IDE plugins, in-app branding).

**File:** [`images/surgewave_mark_adaptive.svg`](images/surgewave_mark_adaptive.svg)
(generated; `colored`, `black` and `white` beside it, and the lockups
`surgewave_lockup_{h,v}_*` with the wordmark in Inter Bold as outlines)
**Inlineable (Liquid):** [`site/_includes/surgewave-mark.svg`](site/_includes/surgewave-mark.svg)
**ViewBox:** `0 0 77.026421 77.673187` (~square)

Behaviour:
- Light background → wave `#33bcff`, arc `#66cfff`, ink `#003e60` (navy)
- Dark background  → wave `#33bcff`, arc `#66cfff`, ink `#ffffff` (white)

Driven by either `prefers-color-scheme: dark` (auto) or, where the SVG is
inlined, the page's theme toggle (`data-theme-resolved="dark"` or
`data-theme="dark"` on `<html>`).

## Package icon

`images/icon.png` (128×128) is the `<PackageIcon>` of every Surgewave NuGet
package (broker, client, connectors, etc.), the Chocolatey package's
`iconUrl` and the source of the MSI installer's `surgewave.ico`. It is the
same tile as `apple-touch-icon.png`: the coloured mark on the light
background, opaque, so it reads on any gallery's surface. `icon-512.png`
is the same tile at 512 px, the web manifest's icon. Both come from the
generator with every other logo file; there is no separate icon drawing.

## Colour palette

| Token | Hex | Usage |
|---|---|---|
| Surgewave Blue (Wave) | `#33bcff` | Wave element of the mark; primary accent across UI |
| Surgewave Light Blue (Arc) | `#66cfff` | The upward arc of the mark |
| Surgewave Navy (Ink) | `#003e60` | Ink element of the mark on light backgrounds |
| White (Ink, dark) | `#ffffff` | Ink element when the surrounding surface is dark |

---

## Things to avoid

- Don't recolour the wave element. The wave is `#33bcff` and the arc
  `#66cfff` everywhere; they anchor brand recognition across both variants.
- Don't add a stroke or outline to the mark. The two-tone fills are
  the entire visual system.
- Don't drop the wave-tail to "simplify" the mark. The diagonal of the
  wave-tail and the C-body is the silhouette signature.
- Don't put the **adaptive** mark on a coloured background that isn't
  near-white or near-black; the ink colour switches on theme, not on
  contrast.

## Regenerating the logos

Every logo file, the package icon included, is committed, so consumers never
need to render it. The drawing and `brand.json` are edited in the Kuestenlogik
repository (`brand/products/surgewave`), never here: the pin test
(`tests/ci/branding-tool.test.mjs`) fails a copy edited in place. After a change
there:

```bash
node tools/branding/vendor.mjs surgewave <this checkout>   # in a clean Kuestenlogik checkout
cd scripts/branding/tool && npm ci && cd ../../..          # once: Playwright and sharp
node scripts/branding/tool/generate-logos.mjs              # writes images/ and its copies
node scripts/branding/tool/generate-logos.mjs --check
```

`Kuestenlogik/Surgewave.Connectors` keeps its own copy of the package icon;
copy `images/icon.png` there when it changes.
